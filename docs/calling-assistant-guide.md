# Личный ассистент, который звонит по телефону: спецификация для сборки

Этот документ написан так, чтобы его можно было целиком отдать AI-кодинговой
платформе (Claude Code, Cursor, Codex и т.п.) и сказать: «собери мне такого
ассистента». Здесь нет готового кода, здесь есть всё, что нужно знать, чтобы
его написать: что должно получиться, из каких сервисов, какие правила
поведения, какие настройки и на какие грабли не наступать.

Как пользоваться:

1. Заведите аккаунты и ключи из раздела 2 (это делает человек, не ИИ).
2. Скопируйте весь документ в чат с кодинговым агентом и добавьте стартовую
   фразу из раздела 10.
3. Проверяйте результат по сценариям из раздела 11.

---

## 1. Что должно получиться

Пользователь пишет боту в Telegram обычным текстом:

> позвони в ресторан «Название» +34 9xx xxx xxx, забронируй столик на двоих на завтра в 20:00

Дальше:

1. Ассистент понимает задачу и собирает бриф звонка: название заведения, номер,
   язык разговора, цель, детали.
2. Бот показывает бриф и спрашивает подтверждение кнопками «Да / Нет».
   Без «Да» звонок не начинается.
3. После «Да» бот запускает звонок через сервис голосовых звонков и сразу
   отвечает «Звоню, отчёт пришлю отдельно». Пользователь может давать другие
   задачи, пока идёт разговор.
4. Голосовой робот звонит с арендованного номера, представляется ассистентом
   владельца, ведёт разговор на нужном языке, проходит автоменю, ждёт на
   удержании, договаривается на имя владельца.
5. Когда разговор закончен, бот присылает отчёт: статус, короткое резюме
   по-русски, длительность, аудиозапись файлом.

Дополнительно:

- «позвони в 18:00» ставит звонок в расписание, `/calls` показывает ждущие
  звонки с кнопкой отмены;
- робот знает свободные окна владельца из Google Calendar и записывает только
  на свободное время;
- `/memory <текст>` пополняет память фактами о владельце (телефон, аллергии,
  номер полиса), робот использует их в разговоре.

Языки звонка: испанский, английский, русский. Легко добавить другие.

## 3. Архитектура

```
Пользователь ⇄ Telegram ⇄ Бот на сервере ⇄ Claude (Anthropic API)
                               │
                               ├── Google Calendar (свободные окна)
                               ├── локальная база (расписание, память, диалог)
                               │
                               └── Retell AI ──► телефон заведения
                                   (агент = слух + мозг + голос + телефония)
```

Ключевое решение: **два разных LLM с разными ролями**.

- **Claude в боте** разбирает текст пользователя, выбирает инструмент,
  собирает бриф. По телефону он никогда не говорит.
- **LLM внутри Retell** ведёт сам разговор по инструкции, которая задаётся
  один раз при создании голосового агента. В бриф конкретного звонка он
  получает только подстановки в эту инструкцию.

Такое разделение даёт короткую задержку в разговоре и позволяет настраивать
голос и поведение робота независимо от бота.

Рекомендуемый стек (можно заменить на любой): Python, `python-telegram-bot`,
Claude Agent SDK (или Messages API с tool use), `retell-sdk`, SQLite, systemd.
Один процесс, без вебхуков: Telegram через long polling, Retell через опрос.
Серверу не нужен публичный HTTPS.

## 4. Голосовой робот в Retell

### 4.1 Сколько агентов и как они создаются

По одному агенту на язык (es, en, ru). У каждого свой промпт, свой голос,
свой код языка (`es-ES`, `en-US`, `ru-RU`). Все агенты используют один
купленный номер.

Требование к реализации: промпты и настройки агентов живут **в коде**, а не в
дашборде. Нужны два скрипта:

- `setup` — разово создаёт агентов (LLM с промптом и инструментами → агент с
  голосом и настройками) и печатает их id для конфига;
- `sync` — идемпотентно накатывает на уже созданных агентов текущие промпт,
  модель, голос и настройки. Запускается после каждой правки промпта.

Без этого через месяц никто не вспомнит, что и где менялось.

### 4.2 Инструкция роботу (промпт)

В промпт через `{{переменные}}` подставляются данные конкретного звонка
(список в 4.5). Ниже правила, которые в промпте обязаны быть, и почему.
Каждое оплачено провальным звонком.

| Правило | Зачем |
|---------|-------|
| «Ты — ассистент {{caller_name}}, звонишь по её поручению. Представляйся: „Здравствуйте, я ассистент {{caller_name}}“. Если спросят, человек ли ты, честно ответь, что ты ИИ-ассистент» | робот действует от имени владельца, но не выдаёт себя за человека. В ЕС это требование закона (AI Act, ст. 50), и просто честно |
| «Ты звонишь в {{business_name}}. Цель: {{objective}}. Детали: {{details}}» | сам бриф |
| «Бронь оформляй на имя {{caller_full_name}}; если просят контактный телефон, продиктуй {{caller_phone}}» | заведению нужны имя и телефон, а не имя робота |
| «О владельце: {{about_me}}. На вопросы о нём отвечай ТОЛЬКО из этих данных. Чего не знаешь (дата рождения, номер полиса, адрес) — не выдумывай, скажи, что уточнишь и сообщишь» | иначе LLM уверенно сочиняет дату рождения и адрес |
| «Свободные окна владельца: {{availability}}. Предлагай и подтверждай только время из них. Если предлагают другое или список пуст — соглашайся предварительно и скажи, что сверишься с расписанием и перезвонишь, если не подойдёт» | запись на занятое время хуже, чем без записи |
| «На удержании (музыка, „все линии заняты“, автоответчик просит подождать) МОЛЧА оставайся на линии сколько потребуется. НИКОГДА не клади трубку, пока ждёшь» | без этого робот вешает трубку на первой же музыке |
| «Если автоменю просит нажать цифру — используй инструмент нажатия цифры, выбирай пункт, ведущий к живому человеку (ресепшн, запись, оператор). Не уверен — нажми 0 или жди» | «para reservas, pulse 2» иначе ставит робота в тупик |
| «Если предлагают написать на email, зайти на сайт или перезвонить позже — НЕ соглашайся. Вежливо скажи, что хочешь решить сейчас по телефону, попроси соединить с тем, кто может помочь, или оставить на линии» | стандартный способ отфутболить звонящего |
| «Попал на голосовую почту, которая только записывает сообщение (не очередь ожидания) — не оставляй сообщение, молча повесь трубку» | сообщения на автоответчик бесполезны |
| «Не вешай трубку сразу после приветствия и до того, как собеседник ответил. Не разобрал — попроси повторить, никогда не завершай звонок из-за плохого звука» | обрывы на первых секундах |
| «Цель подтверждена собеседником → попрощайся ОДНОЙ короткой фразой и сразу заверши звонок инструментом. Никогда не говори вслух „завершаю звонок“. Не растягивай прощание, не повторяй благодарности» | иначе робот тянет прощание по 30 секунд и озвучивает служебные действия |
| «Будь кратким и вежливым, подтверждай детали. Мест нет — спроси альтернативы» | базовые манеры |

Про раскрытие ИИ: соблазн написать «никогда не говори, что ты бот» есть,
потому что некоторые операторы бросают трубку. Не делайте так: робот,
выдающий себя за человека, нарушает ст. 50 AI Act, в Испании обсуждаются
штрафы от €500k. Если трубку бросили, звонок вернётся без договорённости,
и вы позвоните сами.

Для русского промпта: имя владельца передавайте кириллицей, латиницу TTS
читает с неверным ударением. Если владелец женщина, укажите в промпте
женский род.

### 4.3 Инструменты робота

Ровно два, оба обязательны:

- **завершить звонок** (`end_call`) — без него робот не умеет закончить разговор;
- **нажать цифру** (`press_digit`) — без него не проходит автоменю.

### 4.4 Настройки агента

Длительность и тишина:

| Параметр | Значение | Почему |
|----------|----------|--------|
| максимальная длительность звонка | 2 часа (потолок Retell) | ждать оператора «до победного» |
| завершение по тишине | 2 часа, равно максимальной длительности | **музыка на удержании не сбрасывает таймер тишины**: с дефолтом звонок обрывался через 15 с с причиной `inactivity` |
| напоминание при тишине | через 30 с, не более 1 раза | дефолт ~10 с заставлял робота повторно здороваться в паузах |

Голос и латентность (подобрано на тестовых звонках, отправная точка):

| Язык | Голос | Модель голоса | Скорость | Распознавание |
|------|-------|---------------|----------|---------------|
| es | `retell-Andrea` (MiniMax, platform-голос) | по умолчанию | 0.9 | fast |
| en | `11labs-Lily` | `eleven_v3` | 1.0 | fast |
| ru | `11labs-Lily` | `eleven_multilingual_v2` | 1.1 | accurate |

Что выяснилось: голос выбирается только прослушиванием. Для испанского
Cartesia звучала роботом, `eleven_v3` тараторил. Для русского нативного голоса
нет, берётся мультиязычный ElevenLabs, но `eleven_v3` русский роботизирует.

Прочие настройки агента: фоновый шум `coffee-shop` (громкость 1.5 для es,
0.3 для остальных; маскирует синтетическую тишину между репликами),
поддакивание включено с частотой 0.3 (0.8 мешало), `responsiveness` 1,
чувствительность к перебиванию 0.6, экспрессивный режим включён,
динамическая скорость и отзывчивость выключены.

LLM для разговора: Claude Sonnet (внутри Retell). Приоритетная очередь LLM
для es и en включена: вместе с быстрым режимом распознавания это срезало
задержку ответа с 2.3 до 1.7 с. Haiku быстрее ещё на 0.7 с, но суше
формулирует и ловил повторное приветствие.

### 4.5 Что передаётся в звонок (динамические переменные)

При запуске каждого звонка агенту передаются подстановки:

- `business_name`, `objective`, `details` — из брифа;
- `caller_name`, `caller_full_name`, `caller_phone` — из конфига владельца
  (для ru кириллическая форма имени);
- `about_me` — текст памяти владельца целиком;
- `availability` — свободные окна из календаря, формат в 7.1.

Плюс метаданные звонка: язык, чтобы потом понимать, какой агент звонил.

### 4.6 Резюме по-русски

Встроенное резюме Retell только на английском. Нужно кастомное поле
пост-анализа `summary_ru` с описанием: «Краткое саммари разговора СТРОГО
на русском (1–2 предложения): цель, чем закончилось, ключевые договорённости.
Только по-русски, даже если разговор был на другом языке». В отчёте брать его,
при отсутствии падать на английское.

## 5. Ассистент в боте и инструмент «позвонить»

### 5.1 Как устроен ассистент

Claude с системным промптом «ты личный ассистент пользователя в Telegram,
отвечай кратко, по-русски» и набором инструментов. Из релевантного звонкам:

- часовой пояс владельца и текущее время передаются в каждом сообщении;
- контекст диалога сохраняется между сообщениями (сессия на чат), после
  паузы больше 2 часов начинается новая;
- перед необратимыми и внешне видимыми действиями система запрашивает
  подтверждение у пользователя; ассистент не должен дублировать этот вопрос
  текстом.

### 5.2 Инструмент `place_call`

Параметры:

| Параметр | Тип | Описание для модели |
|----------|-----|---------------------|
| `business_name` | строка | название заведения |
| `to_number` | строка | номер в формате E.164 (+34…) |
| `language` | `es` / `en` / `ru` | язык разговора |
| `objective` | строка | цель звонка |
| `details` | строка | детали: дата, время, количество человек, имя, что уточнить |
| `when` | строка, ISO-дата-время | **только** если пользователь явно назвал будущее время («в 18:00», «завтра в 10», «через час»). Если сказано «сейчас» или время не названо — не передавать вообще, звонок идёт немедленно |
| `availability_from` | строка, ISO-дата | начало периода, в котором нужна запись. **Только** если запись явно не на ближайшее время («запишись на октябрь» → первое число октября). Иначе не передавать |

Формулировки с «только» и «не передавать» в описании инструмента важны:
без них модель планировала звонок «на сейчас» и передавала
`availability_from` на любую бронь.

Поведение:

- `when` в будущем (больше чем на минуту) → записать в расписание, вернуть
  «Звонок запланирован на …»;
- иначе → запустить звонок **и сразу вернуть** «Звоню, отчёт пришлю отдельно».
  Инструмент не ждёт конца разговора.

### 5.3 Подтверждение

`place_call` входит в список инструментов, требующих подтверждения. Перед
вызовом бот показывает в Telegram имя инструмента и его аргументы с кнопками
«✅ Да / ❌ Нет» и ждёт нажатия. «Нет» возвращает модели отказ пользователя.
Так владелец видит номер, язык и цель до того, как кто-то снимет трубку.

## 6. Жизненный цикл звонка

### 6.1 Почему инструмент не блокирующий

Звонок может идти час (ожидание оператора). Если инструмент ждёт результата,
чат заблокирован, а агентный цикл упрётся в таймаут. Поэтому инструмент
возвращается сразу, а идентификатор звонка передаётся в фоновую задачу бота,
которая следит за звонком и присылает отчёт отдельным сообщением.

### 6.2 Опрос звонка

- Опрашивать статус каждые 5 с, пока звонок идёт. Потолок ожидания чуть
  больше максимальной длительности звонка (2 ч + запас); по истечении
  считать статус `timeout`.
- После того как звонок закончился, Retell ещё несколько секунд досчитывает
  пост-анализ (резюме, признак успеха). **Ждать его** отдельным циклом
  (до ~12 попыток по 5 с) для звонков с ненулевой длительностью, иначе отчёт
  уходит пустым.

### 6.3 Нормализация статуса

Retell отдаёт три разных поля: статус звонка, причина завершения и пост-анализ
(успех, попал ли на автоответчик). Свести в один статус по правилам, в этом
порядке:

| Условие | Статус |
|---------|--------|
| статус звонка `error` | `failed` |
| статус `not_connected` | `no_answer` |
| статус не `ended` | `in_progress` |
| анализ говорит «автоответчик» или причина `voicemail_reached` | `voicemail` |
| причина `dial_busy` / `dial_failed` / `dial_no_answer` | `no_answer` |
| причина `max_duration_reached` | `timeout` |
| анализ говорит «успешно» | `success` |
| иначе | `completed` |

И поверх: **если звонок короче 10 секунд, статус `success` или `completed`
понижается до `too_short`**. Retell иногда ставит «успешно» и сочиняет резюме
на трёхсекундный звонок, где никто не снял трубку. Без этого правила
пользователь получает «✅ Готово, столик забронирован» на несостоявшийся звонок.

### 6.4 Отчёт в Telegram

Заголовок по статусу:

| Статус | Текст |
|--------|-------|
| `success` | ✅ Готово |
| `completed` | ☑️ Дозвонились, разговор завершён |
| `too_short` | ⚠️ Звонок слишком короткий, вероятно, не удался. Проверь запись |
| `voicemail` | 📭 Попали на автоответчик |
| `no_answer` | 📵 Не дозвонились (занято / нет ответа) |
| `timeout` | ⏱ Звонок прерван по таймауту |
| `failed` | ❌ Звонок не удался |

Затем резюме (`summary_ru`), длительность в секундах, и отдельным сообщением
аудиозапись: скачать по ссылке из Retell и отправить как аудио, при ошибке как
документ.

## 7. Контекст для разговора

### 7.1 Свободные окна из календаря

- Взять события всех календарей владельца на 14 дней вперёд (или начиная с
  `availability_from`).
- Рабочее окно 09:00–21:00 по часовому поясу владельца; вычесть занятое;
  отбросить окна короче 30 минут; сегодняшнее прошедшее время считать занятым.
- Формат для промпта, по строке на день, полностью занятые дни пропускать:

```
2026-09-11 (Fri): 09:00–12:30, 15:00–21:00
2026-09-12 (Sat): 10:00–21:00
```

- Календарь недоступен → передать **пустую строку**, а не «весь день
  свободен». Промпт на пустой список переключается в режим предварительного
  согласия. Ошибка календаря никогда не должна ронять звонок.

### 7.2 Память о владельце

Команда `/memory <текст>` меняет единственную запись профиля: «дата рождения
такая-то», «аллергия на орехи», «номер полиса такой-то», «забудь про
аллергию». Слияние делает дешёвая модель (Haiku) с инструкцией: вернуть
только обновлённый список коротких фактов по строке, сохранять старые факты,
если инструкция их явно не отменяет. `/memory` без текста показывает
текущую память. Весь текст памяти уходит в `{{about_me}}`.

## 8. Отложенные звонки

- Таблица в локальной базе: чат, заведение, номер, язык, цель, детали,
  время срабатывания, статус (`pending` / `done` / `cancelled` / `missed`).
- При постановке — задача таймера на нужное время с допуском ~5 минут на
  опоздание.
- При срабатывании — выполнить звонок целиком (запуск + опрос), прислать
  отчёт и запись, пометить `done`. При ошибке — сообщить «не удалось выполнить
  запланированный звонок».
- При старте бота перечитать `pending`: будущие поставить в таймер,
  просроченные пометить `missed` и написать в чат «⚠️ Пропущен запланированный
  звонок в … (на …), бот был офлайн».
- `/calls` — список ждущих звонков с кнопкой «❌ Отменить» на каждый; отмена
  снимает таймер и помечает `cancelled`.
- Время из `when` без смещения трактовать в часовом поясе владельца.

## 9. Развёртывание и конфигурация

Переменные окружения:

```
TELEGRAM_BOT_TOKEN, ALLOWED_CHAT_IDS (через запятую), TIMEZONE
ANTHROPIC_API_KEY
RETELL_API_KEY, RETELL_FROM_NUMBER (+1…, куплен в Retell)
RETELL_AGENT_ID_ES, RETELL_AGENT_ID_EN, RETELL_AGENT_ID_RU
OWNER_NAME, OWNER_SURNAME, OWNER_NAME_RU, OWNER_SURNAME_RU
OWNER_PHONE (реальный телефон владельца: робот диктует его для брони)
GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, GOOGLE_REFRESH_TOKEN, GOOGLE_CALENDAR_IDS
```

Звонки включаются, только когда заданы ключ Retell, номер и хотя бы один
агент; иначе инструмент `place_call` не регистрируется.

Запуск: systemd-сервис с автоперезапуском, `.env` с правами 600, логи в
journal. Бот отвечает только чатам из `ALLOWED_CHAT_IDS`.

Порядок первого запуска:

1. Купить номер в Retell, вписать ключ и номер.
2. Запустить `setup`, вписать id агентов.
3. Заполнить данные владельца и часовой пояс.
4. Запустить бота, написать «позвони мне на <свой номер> и скажи привет».
5. Послушать запись, поправить промпт и голос, запустить `sync`, повторить.
   Ожидайте 5–10 тестовых звонков на язык до приемлемого результата.

## 11. Сценарии приёмки

Прогнать вручную после сборки, на свой номер и на пару реальных заведений:

- [ ] «позвони мне на <номер> и скажи привет» → приходит запрос «Да/Нет»,
  после «Да» звонок идёт, отчёт и запись приходят отдельным сообщением.
- [ ] Нажать «Нет» → звонка нет, ассистент спокойно отвечает.
- [ ] Не снять трубку → статус `no_answer`, а не «✅ Готово».
- [ ] Снять и сразу положить → `too_short`.
- [ ] Включить автоответчик → `voicemail`, сообщения на нём нет.
- [ ] Поставить на удержание на 3 минуты с музыкой → робот ждёт, не
  вешает трубку, не здоровается повторно.
- [ ] Спросить робота «вы бот?» → честно отвечает.
- [ ] Спросить дату рождения, которой нет в памяти → «уточню и сообщу»,
  не выдумывает.
- [ ] Добавить факт через `/memory`, спросить его в звонке → называет.
- [ ] Предложить время, занятое в календаре → соглашается предварительно и
  обещает перезвонить.
- [ ] «позвони через 3 минуты» → в `/calls` есть запись, звонок идёт вовремя,
  отчёт приходит.
- [ ] Перезапустить бота с ждущим звонком → звонок не теряется; с просроченным
  → сообщение «пропущен».
- [ ] Пока идёт звонок, дать боту другую задачу → отвечает, не ждёт конца звонка.
- [ ] Резюме в отчёте по-русски, даже если разговор был на испанском.

## 12. Чеклист граблей

Всё из реальных звонков. Проверьте, что кодинговый агент это учёл:

- [ ] Таймер тишины равен максимальной длительности, иначе обрыв на hold-музыке.
- [ ] Инструмент нажатия цифры и правило про автоменю в промпте.
- [ ] Правило «не соглашайся на email / сайт / перезвоните позже».
- [ ] Голосовая почта → молча положить трубку.
- [ ] `too_short`: звонок короче 10 с не может быть успешным.
- [ ] Ожидание пост-анализа после конца звонка, иначе пустое резюме.
- [ ] Кастомное `summary_ru`, встроенное резюме только на английском.
- [ ] Кириллическое имя для русского агента.
- [ ] «Не выдумывай» и память через `/memory`.
- [ ] Пустая доступность ≠ полностью свободный день.
- [ ] Инструмент не блокирует ассистента; отчёт отдельным сообщением.
- [ ] Подтверждение кнопками до набора номера.
- [ ] `when` только для явно будущего времени.
- [ ] Отложенные звонки переживают рестарт, просроченные помечаются.
- [ ] Промпты и настройки агентов в коде, скрипт `sync`.
- [ ] Робот представляется ассистентом и честно отвечает, что он ИИ.

## 13. Стоимость

Ориентир на звонок 3–5 минут: Retell (телефония, распознавание, синтез, LLM)
около $0.5–1, номер около $2 в месяц, плюс копейки Anthropic за разбор задачи
в боте, плюс VPS $6–12 в месяц. Часовое ожидание на удержании стоит
соответственно дороже, потолок 2 часа задан сознательно.

## 14. Как расширять

- **Другой голосовой провайдер** (Vapi, Bland, свой пайплайн на Twilio +
  Deepgram + Claude): держите провайдера за интерфейсом «запустить звонок /
  получить статус», нормализуйте его статусы в таблицу из 6.3, остальное не
  меняется.
- **Новый язык**: промпт, голос, код языка, ещё один агент и переменная с его id.
- **Входящие звонки**: Retell умеет, но нужен вебхук, то есть публичный
  HTTPS, которого в этой схеме сознательно нет.
- **Повтор при недозвоне**: по статусу `no_answer` ставить звонок в расписание
  через 15 минут.
